## Guide pour créer et partager une application

Depuis la page `Applications` du catalogue de Jask, vous pouvez créer une application en appuyant sur le bouton `Actions` puis `Créer une application` en haut à droite.

![application_create](@public/applications/create.gif)

<Steps>

### Contexte

Le [**`Contexte`**](/docs/applications/create/actions/context) représente les données d'entrée de votre application. Cette brique déterminera les contraintes imposées à l'utilisateur au lancement de l'application ainsi que son mode de déclenchement (manuel, automatisé...). Pour une déclenchement manuel, l'entrée peut être vide, un texte écrit par l'utilisateur et/ou des documents téléchargés par l'utilisateur lançant l'application.

![application_context](@public/applications/contexte.png)

Ici, sur cet exemple, le contexte accepte seulement du texte utilisateur et le texte à afficher au lancement de l'application est "Renseigner le nom du client / compte"
### Enchaîner les actions

Une fois le contexte configuré, vous pouvez enchainer les actions en cliquant sur le bouton `+` en haut à droite de l'écran.
Il existe une multitude d'actions à disposition pour construire votre workflow métier (voir le tableau en haut de cet article).
Chaque action peut prendre en compte des entrées (inputs) et/ou des sorties (outputs) représentées par des connexions (pins) situées des deux côtés de l'action. Ils vous simplifieront la connexion de l'action ajoutée au reste du workflow.

Les pins situés à gauche de la brique sont des entrées de données qui vont permettre à l'action de s'exécuter.
Les pins situés à droite de la brique sont des sorties de données qui vont permettre de récupérer les résultats de l'action.
Vous pouvez aussi enchaîner les actions en les connectant entre elles.
Pour cela, vous pouvez cliquer sur le pin situé à droite de l'action et le relier au pin situé à gauche d'une autre action.
Les entrées de données de l'action connectée seront automatiquement remplies avec les sorties de données de l'action précédente.

![application_chain](@public/applications/actions.png)


### Enregistrer l'application

Une fois le workflow testé et validé, vous pouvez l'enregistrer en cliquant sur l'icône `Fusée` en haut à droite.

Vous pouvez lui donner un nom et une description puis choisir un tag pour qu'elle soit triée dans la bonne section du catalogue d'applications. 
Enfin, définissez la visibilité de l'application : Toute l'organisation, Moi uniquement ou Personnalisé (Utilisateurs et Groupes spécifiques).

![application_save](@public/applications/deploy.png)

</Steps>

## Exemples d'applications

<details>
<summary>Application simple</summary>
Objectif : Faire un résumé court d’un corpus de fichiers, contenant des éléments graphiques (images, tableaux, graphiques)

L’application prend en entrée une liste de fichiers, qui seront lu avec Vision IA. Cela permet de parcourir l’ensemble du contenu des fichiers, avec de la Vision (à la place de l’OCR) avec le model 4.1 (ici aucune instruction spécifique de vision n’est ajoutée).

Ces fichiers vont ensuite être traité par une brique “Analyse de fichiers” qui a pour objectif de réaliser un résumé court du contexte d’entrée avec le modèle gpt4.1.
L’option “Lire toutes les pages” permet d’assurer que le modèle va parcourir l’intégralité des pages des documents en entrée. En effet, si les fichiers sont trop longs, le contexte du LLM pourrait être dépassé et certaines pages ne pas être parcourues

![simple_app](@public/applications/simple_app.png)
</details>
<details>
<summary>Application moyenne</summary>
Objectif : Trouver des profils qui correspondent à une compétence demandée dans une base SharePoint de CV et scorer les CV trouvés par rapport au besoin

Le contexte permet à l’utilisateur qui démarre l’application de saisir les compétences recherchées dans son projet.

Ces compétences sont passées à un moteur de recherche, dont l’objectif est de restituer une liste de CV, depuis un fichier “CV” contenu dans un SharePoint, par rapport à la compétence saisie en entrée.

Cette liste de document va ensuite être traitée par un prompt qui analyse les CV trouvés et a pour objectif de les scorer par rapport à une série de règles métiers indiquées dans le prompt

![medium_app](@public/applications/medium_app.png)
</details>
<details>
<summary>Application avancée</summary>
Objectif : Analyse d’une entreprise suivant 3 axes Business, Finance, Juridique à partir d’un ensemble documentaire sur l’entreprise

Les documents sur l’entreprise à analyser en entrée sont analysés par 3 agents indépendamment, qui chacun ont des instructions pour analyser le contenu en entrée et faire une restitution spécifique selon des règles métiers.
Le prompt qui suit permet de structurer les rapports individuels de chacun des agents et restructurer les informations selon des règles spécifiés dans le prompt avec un modèle o1-mini dans cet exemple.
La derniere étape permet de générer un document word contenant la synthèse en sortie du prompt.

![advanced_app](@public/applications/advanced_app.png)
</details>
