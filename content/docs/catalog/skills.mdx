## Catalogue de skills

Le catalogue JAsk regroupe tous les skills que vous et votre organisation pouvez utiliser pour enrichir vos agents IA. Un skill est une capacité réutilisable — une action, un calcul, une intégration — que vous attachez à vos agents pour étendre leurs fonctionnalités.

## À quoi ça sert

Les skills permettent à vos agents de :

- Exécuter des actions concrètes (créer un document, envoyer un message)
- Effectuer des calculs ou transformations (analyse financière, génération de rapports)
- Définir quand accéder à des données spécifiques (bases de données, API, fichiers)
- Reproduire des logiques métier standardisées sans réinventer la roue à chaque fois

Plutôt que de réécrire les mêmes instructions pour chaque agent, un skill vous permet de **définir une logique une seule fois, puis de la réutiliser partout**.

![skills](@public/skills_1.png)

## Créer un skill

Un skill est un bloc de logique réutilisable que vous définissez une seule fois et attachez à vos agents selon vos besoins. Créer votre propre skill vous permet de standardiser des instructions,  et des processus sans les répéter pour chaque agent.

La de skills (si vous en avez les permissions) peut être démarrée de 3 manières : 
- Dans le menu, via le bouton `**...**` à droite de `+Chat`
- Dans l'accueil, via le bouton **`Ajouter`** à droite de la barre de recherche du catalogue
- Dans l'onglet **`Réglages`**, sous la menu Agents IA de la section Catalogue

Le formulaire de création s'ouvre avec tous les champs nécessaires pour définir votre skill.

<Steps>
### Informations du skill

- Le nom doit être court et identifiable, sans majuscule ni espace
- La description du skill qui sera utilisée par les agents pour déterminer quand appeler un skill
- Les tags, pour filtrer les skills

<Callout type="info">
les skills natifs de la plateforme sont tous préfixé par `just-xyz`
</Callout>

### Instructions
C'est la partie la plus importante : ici vous décrivez **comment votre skill fonctionne et ce qu'un agent doit faire** quand il l'utilise.

- **Contexte métier** — expliquez pourquoi on fait ça, pas seulement le comment
- **Précises** — dites exactement ce que le skill doit accomplir, pas de généralités vagues
- **Exemples concrets** — incluez des cas d'usage réels, des résultats attendus
- **Étapes ordonnées** — si le processus a plusieurs étapes, numérotez-les

<Callout type="tip">
**Exemple d'instructions faibles :**  
"Analyser les données."
**Exemple d'instructions fortes :**  
* Récupérez le fichier Excel fourni par l'utilisateur. 
* Filtrez les lignes avec un montant > 1000€. 
* Calculez la somme par catégorie et par mois. 
* Créez un graphique en barres avec ces totaux. 
* Générez un résumé en français avec les 3 catégories les plus importantes.
</Callout>



<Callout type="tip">
Les agents comprennent mieux les instructions si vous décrivez le **résultat attendu** en détail. N'hésitez pas à être verbeux dans les instructions d'un skill — ce n'est pas une limite.
</Callout>

## Ajouter des skills supplémentaires

Si votre skill dépend d'autres skills (il en appelle d'autres ou les utilise en arrière-plan), vous pouvez les lister en cliquant sur **+ Cliquez pour ajouter** dans la section **Skills supplémentaires**.

Cela crée une **dépendance** : si un agent utilise votre skill, il aura automatiquement accès aux skills liés.

<Callout type="tip">
Votre skill *Rapport financier complet* peut dépendre de *Extraction de données* + *Génération de graphiques*.
</Callout>


<Callout type="info">
Les dépendances facilitent la composition de skills complexes, mais n'oubliez pas que plus de dépendances = plus de complexité pour l'agent. Gardez les dépendances au minimum.
</Callout>

## Configurer la sécurité et les accès

Définissez la visibilité du skill pour les autres utilisateurs. En fonction des droits donnés, vous pourrez définir si les utilisateurs peuvent uniquement utiliser l'agent ou bien l'éditer et le modifier :
    * **`Privé`** (moi uniquement (par défaut)) : utile en phase de construction de l'agent ou pour des agents personnels
    * **`Toute l'organisation`** : Tous les utilisateurs de votre organisation sont impactés par la visibiltié donnée (utilisation uniquement ou édition)
    * **`Accès restreint`** : Vous sélectionnez un ou plusieurs utilisateurs et vous leur attachez le rôle nécessaire (utilisation ou édition).

<Callout type="warning">
Un skill public fait partie du catalogue partagé. Avant de le rendre public, testez-le avec vos agents et vérifiez que les instructions sont complètes et sans erreurs.
</Callout>
</Steps>

# Extension Web API

L'extension Web API transforme votre agent en véritable pont vers vos systèmes externes. Besoin de consulter votre CRM, créer des rendez-vous, ou récupérer la météo ? Cette extension permet à votre agent d'appeler n'importe quelle API REST comme si c'était un membre de son équipe.

{/* ![Extensions disponibles](@public/settings/ai_extensions/web_api/dashboard.png) */}

## Utilisation

Imaginez pouvoir dire à votre agent : "Trouve-moi le client avec l'email jean.dupont@example.com" et qu'il consulte automatiquement votre CRM. Ou encore : "Crée un rendez-vous demain à 14h avec Marie" et hop, c'est fait dans votre calendrier.

C'est exactement ce que fait cette extension. Elle donne à votre agent la capacité d'interagir avec vos outils métier, sans que vos utilisateurs aient besoin de connaître les détails techniques.

**Quelques exemples d'usage :**

- Chercher des infos clients dans votre CRM
- Créer des rendez-vous automatiquement
- Publier des articles sur votre blog d'entreprise
- Récupérer des données depuis vos systèmes internes
- Consulter des API publiques (météo, taux de change, etc.)

## Créer votre première extension

### Prérequis

- L'adresse de votre API ( `https://api.votreservice.com`)
- Un token ou une clé d'authentification (si votre API l'exige)
- Éventuellement la documentation de l'API, c'est toujours utile

<Callout type="info">
  Vous n'avez pas encore d'API sous la main ? Voyons ensemble comment connecter
  une API météo publique, pour bien comprendre le principe.
</Callout>

![extensions](@public/extensions.png)

### Exemple d'API à utiliser

Créons ensemble une extension fonctionnelle avec une API météo gratuite. Vous pourrez la tester immédiatement ! Faites de même avec votre API si vous en avez une à disposition.

On va se connecter à **Open-Meteo**, une API météo gratuite qui ne nécessite même pas de clé d'authentification. Parfait pour débuter !

**Documentation :** https://open-meteo.com/en/docs

<Steps>
#### Créer l'extension

- Pour créer une extension, rendez-vous dans le menu latéral : **Centre de contrôle IA** → **Extensions IA**
- Une fois dans la liste de vos extensions, cliquez sur le bouton **+** pour en créer une nouvelle
- Un panneau s'ouvre sur la droite avec le formulaire de configuration

{/* ![Formulaire vide](@public/settings/ai_extensions/web_api/form-empty.png) */}

#### Remplir les informations

**Nom** :

```
Météo Paris
```

**Description** :

```
Obtenir la météo actuelle à Paris. À utiliser quand l'utilisateur demande la météo ou le temps qu'il fait à Paris.
```

**Type** :

```
Web API
```

**Endpoint :**

```
https://api.open-meteo.com/v1/forecast
```

**Méthode :** GET

**En-têtes HTTP :**
Laissez vide ! Cette API est totalement ouverte, pas besoin d'authentification.

**Paramètres de requête :**

Cliquez sur **+ Ajouter un paramètre** pour chaque ligne :

```
Clé : latitude
Valeur : 48.8566

Clé : longitude
Valeur : 2.3522

Clé : current
Valeur : temperature_2m,relative_humidity_2m,weathercode

Clé : timezone
Valeur : Europe/Paris
```

<Callout type="info">
  **Pourquoi ces valeurs ?** - `48.8566, 2.3522` = coordonnées de Paris -
  `current` = les données qu'on veut (température, humidité, météo) - `timezone`
  = pour avoir l'heure locale
</Callout>

**Qui peut utiliser cette extension** :

Moi uniquement (pour le test)

#### Valider

Cliquez sur **Valider** pour sauvegarder votre extension.

#### Activer l'extension dans votre Agent IA

Votre extension est créée, mais elle n'est pas encore disponible pour les conversations. Il faut l'activer dans un agent :

1. Allez dans **Agent IA** (menu latéral)
2. Sélectionnez votre agent (par exemple "Agent Opérationnel" ou "Agent Agentique")
3. Dans la section **Outils disponibles**, trouvez "Météo Paris"
4. **Activez le toggle** pour rendre l'outil accessible à cet agent

{/* ![Activation de l'outil](@public/settings/ai_extensions/web_api/activate-tool.png) */}

<Callout type="info">
  Un même outil peut être activé pour plusieurs agents différents. Activez-le
  uniquement pour les agents qui en ont besoin !
</Callout>

#### Tester votre extension

Maintenant, ouvrez une conversation avec votre agent et testez :

```text filename="prompt"
Quel temps fait-il à Paris ?
```

L'agent devrait répondre avec les informations de la météo de Paris :

```text
Agent : [Utilise l'outil Météo Paris]
            À Paris actuellement :
            - Température : 12°C
            - Humidité : 75%
            - Conditions : Partiellement nuageux
```

#### Version avancée : N'importe quelle ville

Une fois que ça marche, vous pouvez améliorer pour gérer toutes les villes avec les [placeholders](/docs/settings/ai_center/ai_extensions/web_api#les-placeholders-valeurs-dynamiques) :

**Modifiez les paramètres de requête :**

```
Clé : latitude
Valeur : {{lat|Latitude de la ville}}

Clé : longitude
Valeur : {{lon|Longitude de la ville}}

Clé : current
Valeur : temperature_2m,relative_humidity_2m,weathercode,windspeed_10m

Clé : timezone
Valeur : auto
```

**Changez aussi la description :**

```
Description : Obtenir la météo actuelle pour n'importe quelle ville du monde.
À utiliser quand l'utilisateur demande la météo ou le temps qu'il fait.
```

Maintenant vous pouvez tester :

```text filename="prompt"
"Météo à New York"
```

```text filename="prompt"
"Quel temps à Tokyo ?"
```

```text filename="prompt"
"Prévisions pour Londres"
```

L'agent trouvera automatiquement les coordonnées !

</Steps>

### Comment ça fonctionne ?

Quand vous demandez "Quel temps fait-il à Paris ?", voici ce qu'il se passe :

1. **L'agent comprend** que vous parlez de météo à Paris
2. **Il sélectionne** votre outil "Météo Paris"
3. **Il appelle** l'URL avec tous les paramètres :
   ```
   https://api.open-meteo.com/v1/forecast?latitude=48.8566&longitude=2.3522&current=temperature_2m,relative_humidity_2m,weathercode&timezone=Europe/Paris
   ```
4. **Il reçoit** les données météo en JSON
5. **Il vous répond** de façon naturelle

### Et voilà !

Vous venez de créer votre première extension qui appelle une vraie API. Le principe est exactement le même pour vos APIs internes (CRM, calendrier, etc.), il suffit d'adapter l'URL et l'authentification.

## Les placeholders (valeurs dynamiques)

Les placeholders, c'est vraiment le cœur du système. C'est ce qui permet à l'agent de transformer une phrase normale en appel d'API.

### Comment ça fonctionne ?

Prenons un exemple concret. Vous avez configuré :

```
Endpoint: https://api.bibliotheque.com/livres/{{isbn|Numéro ISBN du livre}}
```

L'utilisateur demande : "Trouve-moi le livre avec l'ISBN 978-2-1234-5678-9"

Voici ce qui se passe dans les coulisses :

1. L'agent voit qu'il doit extraire un `isbn`
2. Il analyse la phrase et repère "978-2-1234-5678-9"
3. Il construit l'URL : `https://api.bibliotheque.com/livres/978-2-1234-5678-9`
4. Il appelle l'API
5. Il vous retourne le résultat de façon lisible

### Les règles d'écriture

Un placeholder suit toujours ce format :

```
{{nom_de_variable|Description pour l'Agent}}
```

**Pour le nom de variable :**

- Lettres, chiffres et underscore uniquement
- Doit commencer par une lettre
- Pas d'espaces ni de caractères spéciaux

```
✅ {{user_id|...}}
✅ {{firstName|...}}
✅ {{date_debut|...}}

❌ {{user-id|...}}      (tiret interdit)
❌ {{first name|...}}   (espace interdit)
❌ {{123id|...}}        (commence par un chiffre)
```

**Pour la description :**

C'est ici que vous aidez l'agent à comprendre ce qu'il doit chercher. Soyez précis !

Comparez :

```
❌ {{id|ID}}
Trop vague. L'agent ne sait pas quel ID chercher.

✅ {{id|ID numérique unique du client}}
Beaucoup mieux. On sait qu'on cherche un nombre et que c'est lié à un client.

✅ {{date|Date de début au format AAAA-MM-JJ}}
Encore mieux : on précise même le format attendu.
```

### Où les utiliser ?

Vous pouvez mettre des placeholders à 4 endroits différents :

**1. Dans l'URL**

```
https://api.exemple.com/utilisateurs/{{user_id}}/commandes/{{order_id}}
```

**2. Dans les paramètres de requête**

```
search={{terme|Ce qu'on cherche}}
limit={{max|Nombre max de résultats}}
```

**3. Dans le corps JSON (POST/PUT)**

```json
{
  "nom": "{{nom|Nom de famille}}",
  "prenom": "{{prenom|Prénom}}",
  "email": "{{email|Adresse email}}"
}
```

### Bien décrire ses placeholders

La qualité de votre description fait toute la différence. Voici comment améliorer vos descriptions :

| Mauvais exemple        | Bon exemple                                       | Pourquoi c'est mieux              |
| ---------------------- | ------------------------------------------------- | --------------------------------- |
| `{{id\|ID}}`           | `{{id\|ID numérique du client}}`                  | On précise le type et le contexte |
| `{{date\|Date}}`       | `{{date\|Date au format JJ/MM/AAAA}}`             | On indique le format              |
| `{{montant\|Montant}}` | `{{montant\|Montant en euros sans le symbole}}`   | On clarifie l'unité et le format  |
| `{{statut\|Statut}}`   | `{{statut\|Statut : actif, inactif ou suspendu}}` | On liste les valeurs possibles    |

**La formule magique :**

```
[Type de donnée] + [Format si besoin] + [Contexte d'usage]
```

Exemples appliqués :

```
{{telephone|Numéro de téléphone français au format +33XXXXXXXXX}}
{{role|Rôle de l'utilisateur : admin, user ou guest uniquement}}
{{quantite|Quantité en unités, nombre entier entre 1 et 100}}
```

## Exemples d'extensions

Rien de tel que des exemples concrets pour comprendre. Voici deux configurations réelles que vous pouvez adapter.

### Exemple 1 : Recherche client dans le CRM

**Le besoin :** Permettre aux équipes de chercher rapidement un client par son email ou son ID.

{/* ![Config CRM](@public/settings/ai_extensions/web_api/example-crm.png) */}

**Configuration :**

```
Nom : Recherche Client
Description : Trouver les informations d'un client dans notre CRM par son ID, email ou téléphone

Endpoint : https://crm.entreprise.com/api/clients/{{identifiant|ID client, email ou téléphone}}
Méthode : GET

En-têtes :
  Authorization: Bearer VOTRE_TOKEN_CRM
  Content-Type: application/json

Partage : Équipes Ventes et Support
```

**Utilisation en pratique :**

```
User : Cherche le client jean.martin@example.com
Agent : [Appelle l'API avec identifiant="jean.martin@example.com"]
            Voici les informations de Jean Martin :
            - Entreprise : Acme Corp
            - Téléphone : +33 6 12 34 56 78
            - Dernière commande : 15/01/2024

User : Affiche-moi les détails du client 12345
Agent : [Appelle l'API avec identifiant="12345"]
            ...
```

### Exemple 2 : Création de rendez-vous

**Le besoin :** Simplifier la prise de rendez-vous dans le calendrier d'équipe.

**Configuration :**

```
Nom : Créer un Rendez-vous
Description : Planifier des réunions dans le calendrier partagé. Utilisez ceci quand quelqu'un veut réserver, planifier ou créer une réunion.

Endpoint : https://calendrier.entreprise.com/api/events
Méthode : POST

En-têtes :
  Authorization: Bearer VOTRE_TOKEN_CALENDRIER
  Content-Type: application/json

Corps :
{
  "titre": "{{titre|Titre de la réunion}}",
  "date": "{{date|Date au format AAAA-MM-JJ}}",
  "heure_debut": "{{heure|Heure de début HH:MM}}",
  "duree_minutes": {{duree|Durée en minutes}},
  "participants": ["{{email_participant|Email du participant}}"],
  "lieu": "{{lieu|Salle ou lieu de réunion}}",
  "description": "{{description|Ordre du jour ou notes}}"
}

Partage : Toute l'organisation
```

**Utilisation en pratique :**

```
User : Réserve une réunion "Point Projet" demain à 14h pour 1h30
       avec marie@entreprise.com dans la salle Bordeaux.
       On va discuter du planning Q2.

Agent: [Extrait les informations]
            - titre = "Point Projet"
            - date = "2024-01-22"
            - heure = "14:00"
            - duree = 90
            - email_participant = "marie@entreprise.com"
            - lieu = "Bordeaux"
            - description = "Discussion du planning Q2"

            [Appelle l'API]

            Parfait ! J'ai créé la réunion "Point Projet" pour demain
            à 14h dans la salle Bordeaux. Marie recevra une invitation.
```

## Astuces avancées

### Plusieurs placeholders dans l'URL

Vous pouvez mettre autant de placeholders que nécessaire :

```
https://api.exemple.com/users/{{user_id}}/orders/{{order_id}}/items
```

L'agent extraira les deux valeurs de la phrase de l'utilisateur.

### JSON complexes et imbriqués

Pas de problème pour faire des structures profondes :

```json
{
  "client": {
    "identite": {
      "nom": "{{nom|Nom de famille}}",
      "prenom": "{{prenom|Prénom}}"
    },
    "contact": {
      "email": "{{email|Email}}",
      "telephone": "{{tel|Téléphone}}"
    }
  },
  "preferences": {
    "langue": "fr",
    "notifications": {
      "email": true,
      "sms": {{notif_sms|true ou false}}
    }
  }
}
```

Conseil : gardez une indentation claire pour vous y retrouver.

### Combiner plusieurs extensions

L'agent peut utiliser plusieurs outils à la suite pour répondre à une question complexe.

Exemple :

```
User : Quel est le statut de la dernière commande de client@example.com ?

L'agent va :
1. Utiliser l'extension "Recherche Client" pour trouver l'ID
2. Utiliser l'extension "Liste Commandes" avec cet ID
3. Utiliser l'extension "Statut Commande" sur la dernière commande
4. Vous donner le résultat final
```

## Questions fréquentes

<details>
<summary>**Combien d'extensions puis-je créer ?**</summary>

Autant que vous voulez ! Pas de limite. Créez une extension par API ou par cas d'usage selon ce qui vous arrange.

</details>

<details>
<summary>**Puis-je modifier une extension après l'avoir créée ?**</summary>

Oui, cliquez simplement dessus dans la liste pour la réouvrir et la modifier. Les changements prennent effet immédiatement.

</details>

<details>
<summary>**Comment supprimer une extension ?**</summary>

Utilisez l'icône poubelle dans la liste des extensions. Attention, ceci définitif et affecte tous ceux qui l'utilisaient.

</details>

<details>
<summary>**Que se passe-t-il si l'utilisateur oublie un paramètre dans sa question ?**</summary>

L'agent va lui demander de préciser l'information manquante. Par exemple, si quelqu'un demande "Quel temps fait-il ?" sans dire où, l'agent demandera "Pour quelle ville ?".

</details>

<details>
<summary>**Mon API est lente, ça pose problème ?**</summary>

Les appels ont un timeout de 30 secondes. Si votre API répond plus lentement, l'appel sera interrompu. Dans ce cas, il faudra optimiser l'API.

</details>

## Pour aller plus loin

### Ressources utiles

Avant de créer votre extension, testez votre API avec un outil comme [Postman](https://www.postman.com). Ça vous permet de vérifier que tout fonctionne avant de configurer l'extension.

### Codes HTTP à connaître

Quelques codes que vous verrez peut-être dans les erreurs :

- **200** : Tout va bien
- **400** : Requête mal formée (vérifiez vos paramètres)
- **401** : Authentification incorrecte
- **403** : Pas les droits d'accès
- **404** : URL introuvable
- **429** : Trop de requêtes (attendez un peu)
- **500** : Erreur côté API (pas votre faute)

## En résumé

Vous savez maintenant créer des extensions Web API pour votre agent. Les points essentiels :

- Les **placeholders** sont ce qui rend tout ça intelligent
- Des **descriptions claires** = une meilleure extraction par l'agent
- **Testez** toujours avant de partager largement
- Commencez **simple** puis complexifiez au besoin

Besoin d'aide ? Contactez le support ou consultez vos collègues qui ont déjà créé des extensions. Et n'hésitez pas à expérimenter, c'est comme ça qu'on apprend !
